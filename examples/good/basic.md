# ✅ Good Basic Prompt Examples

This file contains examples of well-crafted basic prompts that demonstrate fundamental prompt engineering principles.

## 🎯 Content Creation Prompts

### ✅ Blog Post Writing
**Prompt:**
```
Write a 500-word blog post about the benefits of remote work for small businesses. Target audience: small business owners considering remote work policies. Include:
- 3 main benefits with specific examples
- 1 potential challenge and solution
- A compelling call-to-action
- Use a professional but approachable tone
```

**Why it works:**
- ✅ Specific word count
- ✅ Clear target audience
- ✅ Structured requirements
- ✅ Tone specification
- ✅ Includes call-to-action

### ✅ Product Description
**Prompt:**
```
Create a product description for eco-friendly bamboo toothbrushes. Include:
- Key features and benefits
- Environmental impact compared to plastic brushes
- Target customers: environmentally conscious families
- Length: 2-3 paragraphs
- Tone: informative yet persuasive
- Include a sustainability statistic
```

**Why it works:**
- ✅ Product details specified
- ✅ Comparison element included
- ✅ Target audience defined
- ✅ Length and tone specified
- ✅ Requests specific data inclusion

## 📚 Educational Prompts

### ✅ Concept Explanation
**Prompt:**
```
Explain photosynthesis to a 10-year-old child. Use simple vocabulary, include a real-world analogy, and break it down into 3 main steps. Make it engaging and easy to remember.
```

**Why it works:**
- ✅ Audience age specified
- ✅ Vocabulary level defined
- ✅ Structure requested (3 steps)
- ✅ Tone specification (engaging)
- ✅ Learning objective clear

### ✅ How-to Guide
**Prompt:**
```
Write step-by-step instructions for changing a car tire. Target audience: complete beginners with no mechanical experience. Include:
- Required tools list
- Safety precautions
- 8-10 clear, numbered steps
- Common mistakes to avoid
- When to call for professional help
```

**Why it works:**
- ✅ Task clearly defined
- ✅ Audience skill level specified
- ✅ Complete structure outlined
- ✅ Safety considerations included
- ✅ Practical advice requested

## 💼 Business Communication

### ✅ Professional Email
**Prompt:**
```
Write a professional follow-up email to a potential client who attended our software demo last week but hasn't responded. The email should:
- Reference specific demo highlights
- Address common concerns about implementation
- Include a clear next step
- Maintain friendly but professional tone
- Be concise (under 150 words)
```

**Why it works:**
- ✅ Context provided
- ✅ Specific content requirements
- ✅ Tone specified
- ✅ Word limit set
- ✅ Call-to-action included

### ✅ Meeting Summary
**Prompt:**
```
Create a meeting summary template for project status meetings. Include sections for:
- Meeting details (date, attendees, duration)
- Key discussion points
- Decisions made
- Action items with owners and deadlines
- Next meeting date
Format as a professional document that can be shared with stakeholders.
```

**Why it works:**
- ✅ Template format requested
- ✅ All necessary sections specified
- ✅ Professional formatting required
- ✅ End-use context provided

## 📊 Data and Technical

### ✅ Code Explanation
**Prompt:**
```
Explain this Python function in simple terms for someone learning programming:

def calculate_compound_interest(principal, rate, time, compounds_per_year):
    return principal * (1 + rate/compounds_per_year) ** (compounds_per_year * time)

Include:
- What the function does
- Each parameter's purpose
- A simple example with numbers
- Why compound interest matters
```

**Why it works:**
- ✅ Code provided for context
- ✅ Target audience specified
- ✅ Specific explanation elements requested
- ✅ Example requested
- ✅ Practical relevance included

### ✅ Technical Documentation
**Prompt:**
```
Write API documentation for a user authentication endpoint. Include:
- Endpoint URL and method
- Required parameters and data types
- Response format and status codes
- Error handling examples
- Code examples in Python and JavaScript
Target audience: developers integrating our API for the first time.
```

**Why it works:**
- ✅ Specific documentation type
- ✅ Complete structure outlined
- ✅ Multiple code examples requested
- ✅ Target audience defined
- ✅ Error handling included

## 🎯 Key Principles Demonstrated

### Clarity and Specificity
- Every prompt clearly states what is needed
- Specific requirements eliminate ambiguity
- Word counts and formats are specified
- Target audiences are clearly defined

### Structure and Organization
- Requirements are broken into clear components
- Bullet points organize complex requests
- Templates and frameworks are specified
- Logical flow is maintained

### Context and Constraints
- Background information is provided
- Limitations and boundaries are set
- Tone and style are specified
- End-use context is explained

### Actionability
- Requests lead to usable outputs
- Practical applications are considered
- Next steps are often included
- Implementation details are specified

## 🎓 Key Takeaways

1. **Specificity trumps brevity** - Better to be detailed than vague
2. **Context creates clarity** - Always provide relevant background
3. **Structure guides output** - Organize your requirements clearly
4. **Audience awareness matters** - Tailor language and complexity
5. **Constraints enable creativity** - Limitations often improve results
