# 🧩 Prompt Patterns: Proven Templates for Consistent Results

Prompt patterns are reusable templates and structures that have been proven to work across different scenarios. This guide covers the most effective patterns for various use cases, helping you build a toolkit of reliable prompt structures.

## 🎯 What Are Prompt Patterns?

Prompt patterns are standardized frameworks that provide consistent structure for different types of AI interactions. Think of them as architectural blueprints - they give you a proven foundation to build upon, while allowing customization for specific needs.

### Benefits of Using Patterns
- **Consistency**: Predictable results across similar tasks
- **Efficiency**: Faster prompt creation using proven structures
- **Scalability**: Easy to train teams and maintain quality
- **Reliability**: Reduced risk of poor outputs
- **Learning**: Faster skill development through pattern recognition

## 📋 Essential Prompt Patterns

### 1. The RTFM Pattern (Role-Task-Format-Metric)

**Structure:**
```
Role: You are a [ROLE/EXPERT TYPE]
Task: [SPECIFIC TASK/OBJECTIVE]
Format: [OUTPUT STRUCTURE/STYLE]
Metric: [SUCCESS CRITERIA/CONSTRAINTS]
```

**Example:**
```
Role: You are a senior marketing strategist with 10+ years in B2B SaaS
Task: Analyze our competitor's pricing strategy and identify opportunities
Format: Executive summary with 3 key insights and 2 action items
Metric: Focus on actionable insights that could impact Q4 revenue by 15%+
```

**Best For:** Professional analysis, business tasks, consulting-style outputs

---

### 2. The Chain-of-Thought Pattern

**Structure:**
```
[PROBLEM STATEMENT]
Let's work through this step by step:
1. First, [STEP 1]
2. Then, [STEP 2]  
3. Next, [STEP 3]
4. Finally, [CONCLUSION]
```

**Example:**
```
Calculate the ROI of implementing a customer chatbot for our e-commerce site.

Let's work through this step by step:
1. First, identify current customer service costs (staff time, response delays)
2. Then, estimate chatbot implementation and maintenance costs
3. Next, calculate potential savings and efficiency gains
4. Finally, determine payback period and 3-year ROI

Show your reasoning for each step.
```

**Best For:** Complex calculations, logical reasoning, problem-solving, educational content

---

### 3. The Persona Pattern

**Structure:**
```
You are [DETAILED PERSONA DESCRIPTION].
Your background: [RELEVANT EXPERIENCE/KNOWLEDGE]
Your communication style: [TONE/APPROACH]
Your goal: [WHAT YOU'RE TRYING TO ACHIEVE]

Given this context: [SITUATION]
[SPECIFIC REQUEST]
```

**Example:**
```
You are Sarah, a experienced product manager at a fast-growing fintech startup. 
Your background: 8 years in product management, launched 12+ features, data-driven decision maker
Your communication style: Direct, analytical, but empathetic to user needs
Your goal: Increase user engagement while maintaining security standards

Given this context: User feedback shows our security onboarding is too complex
Write a product requirements document for simplifying the KYC process.
```

**Best For:** Consistent voice, specific expertise, role-playing scenarios

---

### 4. The Comparison Matrix Pattern

**Structure:**
```
Compare [OPTION A] vs [OPTION B] vs [OPTION C] across these dimensions:
- [CRITERION 1]: [DESCRIPTION]
- [CRITERION 2]: [DESCRIPTION]  
- [CRITERION 3]: [DESCRIPTION]

Format as a comparison table with:
- Scores (1-5 scale)
- Brief explanations
- Final recommendation with reasoning
```

**Example:**
```
Compare React vs Vue vs Angular for our new web application across these dimensions:
- Learning curve: How quickly can our team adopt it?
- Performance: Speed and efficiency for our use case
- Community support: Documentation, libraries, long-term viability
- Integration: How well does it work with our existing Node.js backend?

Format as a comparison table with:
- Scores (1-5 scale) 
- Brief explanations for each score
- Final recommendation with reasoning based on our team of 4 mid-level developers
```

**Best For:** Decision-making, technology selection, vendor evaluation

---

### 5. The Before/After Transformation Pattern

**Structure:**
```
Current State: [DETAILED DESCRIPTION OF CURRENT SITUATION]
Desired State: [CLEAR VISION OF GOAL STATE]
Transformation: [SPECIFIC REQUEST FOR CHANGE]

Requirements:
- [REQUIREMENT 1]
- [REQUIREMENT 2]
- [REQUIREMENT 3]

Show the transformation from current to desired state.
```

**Example:**
```
Current State: Our customer onboarding emails are generic, text-heavy, and have a 12% open rate. New users often don't complete setup within the first week.

Desired State: Personalized, engaging email sequence that guides users through setup with 40%+ open rates and 80% setup completion.

Transformation: Redesign our 5-email onboarding sequence to be more engaging and effective.

Requirements:
- Personalized content based on user's selected use case
- Visual elements and clear CTAs
- Progressive disclosure of features
- A/B testable subject lines

Show the transformation from current to desired state with specific email examples.
```

**Best For:** Improvement projects, redesigns, optimization tasks

---

### 6. The Question Ladder Pattern

**Structure:**
```
I need to understand [TOPIC/SITUATION] deeply.

Please ask me 5 clarifying questions that will help you provide the most relevant and useful response. After I answer, provide your analysis/recommendations.

Focus your questions on:
- [AREA 1]
- [AREA 2]  
- [AREA 3]
```

**Example:**
```
I need to understand the best marketing strategy for launching our new mobile app.

Please ask me 5 clarifying questions that will help you provide the most relevant and useful marketing strategy. After I answer, provide your recommendations.

Focus your questions on:
- Target audience and user personas
- App functionality and unique value proposition
- Budget and timeline constraints
- Competition and market positioning
```

**Best For:** Complex planning, consultative analysis, personalized recommendations

---

### 7. The Constraints-First Pattern

**Structure:**
```
I need [DESIRED OUTCOME] with these non-negotiable constraints:

Hard Constraints (cannot be changed):
- [CONSTRAINT 1]
- [CONSTRAINT 2]

Soft Constraints (flexible):
- [PREFERENCE 1] 
- [PREFERENCE 2]

Given these limitations: [SPECIFIC REQUEST]
```

**Example:**
```
I need a team building activity for our remote engineering team with these non-negotiable constraints:

Hard Constraints (cannot be changed):
- Must be done virtually over video call
- Maximum 90 minutes duration
- All team members in different time zones (US, Europe, Asia)
- Budget under $200 total

Soft Constraints (flexible):
- Prefer interactive over passive activities
- Something that builds actual working relationships
- Avoid typical "icebreaker" games

Given these limitations: Design a team building session that actually strengthens our engineering collaboration.
```

**Best For:** Resource-constrained projects, compliance requirements, technical limitations

---

### 8. The Multi-Perspective Pattern

**Structure:**
```
Analyze [SITUATION/DECISION] from these different perspectives:

1. [STAKEHOLDER 1] perspective: [THEIR CONCERNS/PRIORITIES]
2. [STAKEHOLDER 2] perspective: [THEIR CONCERNS/PRIORITIES]  
3. [STAKEHOLDER 3] perspective: [THEIR CONCERNS/PRIORITIES]

For each perspective, address:
- Key concerns and priorities
- Potential objections or resistance
- What success looks like to them
- Recommendations tailored to their needs
```

**Example:**
```
Analyze our plan to implement AI customer service chatbots from these different perspectives:

1. Customer perspective: People calling for support who want quick, accurate help
2. Customer service team perspective: Current agents who might worry about job security
3. Executive perspective: Leadership focused on cost reduction and efficiency metrics

For each perspective, address:
- Key concerns and priorities they would have
- Potential objections or resistance to the change  
- What success looks like from their viewpoint
- Recommendations for addressing their specific needs
```

**Best For:** Change management, stakeholder analysis, conflict resolution

---

### 9. The Iterative Refinement Pattern

**Structure:**
```
Create [INITIAL OUTPUT] for [PURPOSE].

Then, review and improve it by:
1. Identifying [SPECIFIC IMPROVEMENT AREA 1]
2. Enhancing [SPECIFIC IMPROVEMENT AREA 2]  
3. Optimizing for [SPECIFIC GOAL]

Show both the initial version and the refined version, explaining the improvements made.
```

**Example:**
```
Create a cold outreach email for our web design services targeting small business owners.

Then, review and improve it by:
1. Identifying ways to make it more personalized and less generic
2. Enhancing the value proposition to be more compelling
3. Optimizing for higher response rates based on cold email best practices

Show both the initial version and the refined version, explaining the specific improvements made and why they should increase response rates.
```

**Best For:** Content creation, copywriting, design iteration

---

### 10. The Evidence-Based Pattern

**Structure:**
```
Make a case for [POSITION/RECOMMENDATION] using:

Evidence Types:
- Data/Statistics: [SPECIFIC METRICS NEEDED]
- Expert Opinions: [RELEVANT AUTHORITY SOURCES]
- Case Studies: [SIMILAR SITUATIONS/PRECEDENTS]
- Logical Arguments: [REASONING FRAMEWORK]

Structure your argument as:
1. Executive Summary
2. Supporting Evidence  
3. Counter-arguments and responses
4. Conclusion and call to action
```

**Example:**
```
Make a case for implementing a 4-day work week at our software development company using:

Evidence Types:
- Data/Statistics: Productivity metrics, employee satisfaction studies, industry benchmarks
- Expert Opinions: Research from workforce management experts, successful company leaders
- Case Studies: Similar tech companies who've implemented 4-day weeks
- Logical Arguments: Impact on recruitment, retention, and company culture

Structure your argument as:
1. Executive Summary (why this makes business sense)
2. Supporting Evidence (organized by evidence type)
3. Counter-arguments and responses (addressing common objections)
4. Conclusion and implementation recommendations
```

**Best For:** Business proposals, research presentations, persuasive writing

## 🎨 Creative and Specialized Patterns

### The Story Structure Pattern
```
Create a [CONTENT TYPE] following this narrative structure:

Setup: [CONTEXT/BACKGROUND]
Conflict: [CHALLENGE/PROBLEM]
Resolution: [SOLUTION/OUTCOME]
Lesson: [KEY TAKEAWAY]

Make it [TONE/STYLE] and ensure it resonates with [TARGET AUDIENCE].
```

### The Feature-Benefit-Proof Pattern
```
For [PRODUCT/SERVICE], create marketing copy using:

Feature: [WHAT IT DOES]
Benefit: [WHY IT MATTERS TO CUSTOMER]  
Proof: [EVIDENCE/CREDIBILITY]

Repeat for top 3 features, then add compelling call-to-action.
```

### The Problem-Agitation-Solution Pattern
```
Address [TARGET AUDIENCE'S] pain point:

Problem: [CLEARLY IDENTIFY THE ISSUE]
Agitation: [AMPLIFY THE CONSEQUENCES/FRUSTRATION]
Solution: [PRESENT YOUR OFFERING AS THE ANSWER]

Tone: [EMPATHETIC/URGENT/PROFESSIONAL]
Goal: [SPECIFIC ACTION YOU WANT THEM TO TAKE]
```

## 🔧 Pattern Selection Guide

### For Business Analysis
- **RTFM Pattern**: Executive summaries, strategic analysis
- **Comparison Matrix**: Vendor selection, option evaluation
- **Multi-Perspective**: Stakeholder analysis, change management

### For Content Creation
- **Persona Pattern**: Consistent brand voice, character development
- **Before/After**: Transformation stories, case studies
- **Story Structure**: Engaging narratives, marketing content

### For Problem Solving
- **Chain-of-Thought**: Complex reasoning, troubleshooting
- **Constraints-First**: Resource-limited projects, technical solutions
- **Question Ladder**: Consultative analysis, needs assessment

### For Technical Tasks
- **Evidence-Based**: Research reports, technical proposals
- **Iterative Refinement**: Code optimization, design improvement
- **Step-by-Step**: Documentation, tutorials, procedures

## 🧪 Pattern Customization and Combination

### Combining Patterns
You can combine multiple patterns for complex tasks:

```
[Persona Pattern] + [Chain-of-Thought Pattern]:

You are a experienced UX researcher with 10+ years at tech companies.
Your approach: Data-driven, user-centered, methodical analysis.

Analyze our mobile app's user onboarding flow step by step:
1. First, evaluate the current user journey from download to first value
2. Then, identify specific friction points using UX heuristics  
3. Next, prioritize issues based on user impact and development effort
4. Finally, recommend 3 specific improvements with expected outcomes

Show your reasoning at each step and reference UX best practices.
```

### Pattern Adaptation
Modify patterns for your specific context:

**Original RTFM Pattern:**
```
Role + Task + Format + Metric
```

**Adapted for Creative Tasks:**
```
Persona + Creative Goal + Style Constraints + Success Criteria
```

## 📊 Pattern Performance Optimization

### Testing Pattern Effectiveness

1. **A/B Test Pattern Variations**
```
Version A: Direct instruction
"Write a product description for wireless headphones."

Version B: RTFM Pattern
"Role: Expert copywriter for consumer electronics
Task: Write compelling product description for wireless headphones
Format: 2-3 paragraphs with bullet points for key features
Metric: Focus on benefits that drive purchase decisions"
```

2. **Measure Pattern Consistency**
- Use the same pattern for similar tasks
- Track output quality and relevance
- Note which patterns work best for different team members

3. **Refine Based on Results**
- Keep successful elements
- Modify or remove ineffective components
- Document pattern improvements

## 🎯 Advanced Pattern Techniques

### 1. **Conditional Patterns**
Patterns that adapt based on input:

```
If [AUDIENCE] is technical, use [TECHNICAL APPROACH]
If [AUDIENCE] is non-technical, use [SIMPLIFIED APPROACH]
If [URGENCY] is high, prioritize [QUICK WINS]
If [BUDGET] is limited, focus on [LOW-COST OPTIONS]
```

### 2. **Nested Patterns**
Patterns within patterns for complex tasks:

```
Main Pattern: Multi-Perspective Analysis
Nested Pattern: For each perspective, use Evidence-Based reasoning
Sub-Pattern: For each piece of evidence, use Chain-of-Thought validation
```

### 3. **Progressive Patterns**
Patterns that build complexity over iterations:

```
Round 1: Use Basic Structure Pattern → Get initial output
Round 2: Apply Refinement Pattern → Improve quality  
Round 3: Use Evidence-Based Pattern → Add credibility
Round 4: Apply Persona Pattern → Adjust tone and voice
```

## 🚀 Building Your Pattern Library

### Essential Patterns to Master First:
1. **RTFM Pattern** - Most versatile for professional tasks
2. **Chain-of-Thought** - Critical for complex reasoning

### Pattern Development Process:
1. **Identify Recurring Tasks**: What do you do repeatedly?
2. **Analyze Successful Prompts**: What structure worked well?
3. **Create Template**: Abstract the successful structure
4. **Test with Variations**: Validate across different scenarios
5. **Document and Share**: Make it reusable for others
6. **Iterate Based on Feedback**: Continuous improvement

### Team Pattern Adoption:
- Start with 2-3 core patterns
- Provide training and examples
- Create cheat sheets and quick reference guides
- Encourage experimentation and sharing
- Regularly review and update patterns
